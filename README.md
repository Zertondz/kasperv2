# mangen

Генератор манифеста каталога на C11 и POSIX: для каждого файла выводит путь
относительно каталога и CRC-32 содержимого.

```
$ mangen example
file_1.txt : CBF43926
file_2.png : 00000000
dir_1/file_4 : 363A3020
dir_2/dir_3/file_7.txt : CBF43926
```

## Сборка и тесты

CMake собирает `build/mangen`, цель `check` запускает тесты:

```sh
cmake -S . -B build
cmake --build build
cmake --build build --target check
```

GNU make собирает `./mangen`:

```sh
make
make test
make clean
```

Автор для `-v` задаётся через `-DMANGEN_AUTHOR="Имя"` в CMake или `make AUTHOR="Имя"`.

Тесты лежат в `tests/run_tests.sh`. Они проверяют вывод, опции, ссылки, спецсимволы
в именах, ошибки и коды возврата.

## Использование

```
mangen [DIR_PATH] [OPTIONS]
mangen -c MANIFEST
```

Без `DIR_PATH` манифест строится для текущего каталога.

| Опция         | Описание |
|---------------|----------|
| `-h`          | справка и выход |
| `-v`          | версия, git commit hash и автор, выход |
| `-e PATTERN`  | исключить файлы и каталоги с подходящим именем, можно указывать несколько раз |
| `-s`          | дописать в конец строку `#SHA256 : <hash>` |
| `-c MANIFEST` | проверить эту строку, `-` означает stdin |
| `--`          | конец опций |

Коды возврата:

- `0` — успех;
- `1` — ошибка доступа к файлам или не пройдена проверка `-c`;
- `2` — неверные аргументы.

Ошибки выводятся в stderr, обход при этом продолжается.

## Принятые решения

**Хэш.** CRC-32: 8 hex-цифр, как в примере из задания, быстрый и простой. Он ловит
случайные изменения, но не защищает от намеренной подмены.

**Порядок вывода.** В каждом каталоге сначала файлы, затем подкаталоги, те и другие
отсортированы через `strcmp`. Поэтому вывод не зависит от порядка `readdir`.

**Типы записей:**

- ссылка на файл хэшируется по содержимому цели;
- ссылка на каталог не обходится, это защита от циклов;
- битые ссылки, FIFO, сокеты и устройства пропускаются, чтение FIFO заблокировало бы утилиту;
- недоступная цель ссылки или цикл ссылок дают ошибку и код `1`;
- скрытые файлы включаются в манифест.

**Спецсимволы в именах.** Перевод строки выводится как `\n`, обратный слэш как `\\`,
поэтому каждому файлу соответствует одна строка.

**Шаблоны `-e`.** `.` — любой символ, `*` — любая последовательность, `\` экранирует
следующий символ. Шаблон сравнивается с именем целиком на любой глубине, исключённый
каталог пропускается со всем содержимым.

**Версия.** `-v` выводит `mangen 1.0.0, commit 1a2b3c4`. Суффикс `-dirty` означает
незакоммиченные изменения, `unknown` — сборку вне git-репозитория.

## Контроль целостности

```sh
mangen project -s > manifest.txt
mangen -c manifest.txt
```

`-s` дописывает SHA-256 всех предыдущих байт манифеста. `-c` пересчитывает его и выводит
`manifest.txt: OK` с кодом `0`. Изменение, вставка, удаление строк и обрезка дают код `1`.

Ограничения:

- `-c` проверяет, что манифест дошёл без искажений, но не что он полный: о файлах, которые
  не удалось прочитать, отправитель узнаёт из stderr и кода `1`;
- это защита от случайных ошибок канала: злоумышленник может пересчитать SHA-256, против
  него нужен HMAC с общим ключом или цифровая подпись.

## Структура

```
src/main.c        аргументы, точка входа
src/manifest.c/h  обход каталога, строки манифеста
src/crc32.c/h     хэш файлов
src/sha256.c/h    хэш манифеста
src/integrity.c/h запись и проверка строки #SHA256
src/pattern.c/h   шаблоны -e
src/util.c/h      ошибки, память, пути
src/version.h.in  шаблон version.h
cmake/GitVersion.cmake  генерация version.h
tests/run_tests.sh      end-to-end тесты
```
